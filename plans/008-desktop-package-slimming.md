## Why this matters

The packaged app's `app.asar` is **208MB with 25,139 node_modules entries**
(measured at `dist/mac-arm64/kiri.app/Contents/Resources/app.asar` at the
planned-at commit). electron-builder includes every production `dependency`
from `package.json` automatically — `build.files` listing only `dist/**` etc.
does not exclude them. But most of those dependencies are already **bundled**
into the build outputs: the client is fully bundled into `dist/client`, and
client-only packages (react, react-markdown, shiki, @pierre/diffs with its
~9MB of grammars, lucide-react, all four @fontsource packages, @xterm browser
addons) are never `require()`d by the Node backend at runtime. Two packages
(`fast-check`, `pure-rand`) are in `dependencies` despite having **zero
imports under `src/`** (verified by grep — they are test-only). Every
unnecessary megabyte is paid in download size, install size, and asar parse
time at backend startup.

## Steps

### Step 0: Baseline

Run `pnpm verify:desktop:package` once unmodified to prove the gate is green
before you touch anything, and record asar size + entry count (commands
above). If the gate is red at baseline, STOP — report, don't fix.

### Step 1: Build the evidence table of true runtime externals

Determine what the shipped JS actually resolves from node_modules:

```bash
# bare-import specifiers the SSR server bundle left external
grep -ohE "from ?\"[^\".][^\"]*\"|require\\(\"[^\".][^\"]*\"\\)|import\\(\"[^\".][^\"]*\"\\)" dist/server/server.js dist/server/**/*.js 2>/dev/null | sort -u
# same for the CLI bundle and the backend script
grep -ohE "from ?\"[^\".][^\"]*\"|require\\(\"[^\".][^\"]*\"\\)" dist/cli/*.mjs scripts/kiri-desktop-backend.mjs | sort -u
```

(Adjust quoting for single-quoted emits; check both.) Strip `node:` builtins
and `electron`. The survivors — plus their transitive needs, which pnpm
handles — are the packages that MUST stay in `dependencies`. Expect
`srvx`, `node-pty`, `ws`, and possibly `@xterm/headless`,
`@xterm/addon-serialize`, `@xterm/addon-unicode11`, `effect`/`@effect/*`,
`zod`, `@modelcontextprotocol/sdk` — but trust the grep output, not this
expectation. Anything that appears bundled (no bare import in dist) is a
move candidate.

Record the table (package → keep/move + the evidence line) in the PR
description.

### Step 2: Move the zero-risk pair first

`fast-check` and `pure-rand` have no imports under `src/` at all
(`grep -rn "fast-check\|pure-rand" src/` → no matches at planning time;
re-verify). Move both to `devDependencies`, `pnpm install`, then run the full
gate.

**Verify**: `pnpm typecheck && pnpm test:unit && pnpm verify:desktop:package` → all green. Commit.

### Step 3: Move client-only packages in small batches

Based on Step 1's table, move in batches of 3-6 with the full gate between
batches. Suggested batch order (stop moving anything Step 1 marked "keep"):

1. Fonts + icons: `@fontsource-variable/geist`, `@fontsource/fira-code`,
   `@fontsource/ibm-plex-mono`, `@fontsource/jetbrains-mono`, `lucide-react`.
2. Markdown/diff UI: `react-markdown`, `remark-gfm`, `@pierre/diffs`,
   `@pierre/trees`, `shiki` (shiki is the single biggest tree — ~9MB+).
3. Browser xterm: `@xterm/xterm`, `@xterm/addon-fit`, `@xterm/addon-webgl`,
   `@xterm/addon-ligatures` (NOT the headless/serialize/unicode11 ones unless
   Step 1 proved them bundled).
4. React + TanStack: `react`, `react-dom`, `@tanstack/react-query`,
   `@tanstack/react-router`, `@tanstack/react-router-ssr-query`,
   `@tanstack/react-start` — **highest risk batch**: the SSR server bundle
   may import these at runtime. Only attempt if Step 1 showed no bare imports
   of them in `dist/server/`; expect to revert this batch if the packaged-app
   contract test fails to serve the UI.

After each batch: `pnpm install`, full gate, commit on green; `git checkout -- package.json pnpm-lock.yaml && pnpm install` (revert) on red, then continue
with the next batch.

**Verify (each batch)**: `pnpm verify:desktop:package` → exit 0, and launch
check: `pnpm dist:desktop`-built app starts and serves the board (the
contract test asserts this; a manual open of the app from `dist/mac-arm64`
is the belt-and-braces check on the final state).

### Step 4: Measure and record

Re-run the asar measurements. Expected outcome: entry count drops by
thousands and size by tens of MB (shiki + fonts + react-ecosystem trees
dominate). Record before/after in the PR description and in the plans index
row.

**Verify**: final `pnpm verify && pnpm verify:desktop:package` → all green.

## Maintenance notes

- The invariant this plan establishes: **`dependencies` = what the packaged
  Node backend resolves at runtime; everything bundled-at-build-time lives in
  `devDependencies`.** New packages added to the client must go to
  devDependencies; reviewers should challenge any `dependencies` addition
  that no `dist/` output imports bare.
- A follow-up with a bigger ceiling (deliberately not attempted here): make
  `dist/server/server.js` and the backend script fully self-contained
  (bundle srvx/effect/ws/xterm-headless too, keep only `node-pty` external
  for its native module), dropping node_modules from the asar almost
  entirely. That requires vite/esbuild config work and careful native-module
  handling — size the win against this plan's result first.
- `knip` (`pnpm knip:report`) can help keep the dependency split honest over
  time; consider tightening its config once this lands.
