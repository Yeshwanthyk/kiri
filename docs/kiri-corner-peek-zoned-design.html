Shape

The chosen UI structure.

This page collapses the previous options into one concrete direction: Corner Peek, visible movable resource tabs, scratchpad defaulting to the end, one movement model.

Canvas primary

The selected resource gets the full app stage. This is where chat, diffs, terminal, and scratchpad content render.

Resource Tabs project-local

Agent sessions, terminals, and scratchpad are peers. Tabs are scoped to the selected project and all share the same move/reorder primitive.

Corner Peek orientation

The top-right chip is the replacement for the sidebar. It expands on arrow, hover/click, or holding Cmd.

Rules

Primitive rules to plan against.

These are the design contracts I would turn into implementation tasks once we move from UI shaping into planning.

New agent

Creates a movable tab before the scratchpad by default. It never creates a sidebar card.

Scratchpad

Defaults to the final project tab, but participates in the same move/reorder model. It is shared project/workspace context, not owned by one session.

All resources

Agents, terminals, and scratchpad are all movable. Reorder, detach, and alignment use one primitive instead of special-cased surfaces.

Terminal

Movable tab. A terminal may be attached to an agent, detached into the project tab strip, or moved between terminal layouts.

Corner Peek

Up/down moves projects. Left/right moves resource tabs. Holding Cmd pins the map and shows alignment before selection.

Hidden projects

Hidden projects belong to the Projects page. Corner Peek can show count/status, but management stays in the full-screen register.

Flows

First-pass interaction flow.

This is the smallest coherent behavior set for the prototype.

1

Start agent

New agent appears as a movable project tab before the scratchpad by default.

2

Move resource

Reorder an agent, detach a terminal, or pull scratchpad forward using the same tab motion.

3

Open scratchpad

Scratchpad opens from the default final position, then can move like any other resource.

4

Peek projects

Corner Peek shows lanes and compact tab state without a sidebar.

5

Switch fast

Up/down changes project. Left/right changes tab inside project.

Decision gates

identity

Stable tab ids for agents, terminals, and scratchpad so reorder survives reloads.

ownership

Project owns resource order. Agent owns session state. Scratchpad owns shared project context.

movement

Drag, keyboard, and Corner Peek all call the same move primitive.

persistence

Remember active resource, tab order, terminal tabs, and scratchpad position as frontend shell state.

restart

Reload restores where everything was without changing SQLite, MCP, CLI, or runtime contracts.

App-level page locks

projects

Full-screen Project Register. It owns add, choose directory, reorder, hide/unhide, delete, and hidden shelf management.

hidden

Hidden projects sit at the bottom of the register. Corner Peek shows a compact count/status only.

settings

Full-screen Control Surface. Keep the existing palette, chat, connect, and keyboard grouping.

actions

Project action runs can later create terminal tabs for servers, tests, and typecheck.

Surface contract

entry

Corner Peek footer/action, command palette, and existing project button all open the same page.

add row

Name, directory, optional id, Choose, Add. Compact command row; it should not dominate the page.

visible

Ordered rows with name, path, session/resource summary, running status, reorder, hide, delete.

hidden

Bottom shelf inside the page. Hidden projects can unhide or delete; they do not appear as board chrome.

Behavior lock

persist

Use existing project order and hidden metadata. Do not add a schema or app-core concept.

delete

Keep confirmation. Delete only Kiri metadata; never delete the repo directory.

reorder

Visible-only order. Hidden project order can wait unless current persistence already supports it cleanly.

peek

Corner Peek shows visible projects plus a hidden count/action. The shelf itself lives here.

Settings

Control Surface stays full-screen.

Settings is where global preferences live. It should feel like a Mac app control panel: dense, calm, keyboard-friendly, and separate from project resource movement.

Locked shape: keep the full-screen page with left index and grouped panels.

The current direction is already close. Polish the page around the new shell language instead of folding it into Corner Peek or the tab strip.

Surface contract

entry

Corner Peek app action, command palette, and current Settings trigger open the same page.

layout

Top bar with board return, breadcrumb, sticky left index, main cards. No sidebar and no modal.

sections

Palette, Chat typography, Connect phone board, Keyboard. Add Shell only when layout reset/preferences are real.

return

Back to board restores the selected project and selected resource exactly as the shell left them.

Behavior lock

scope

Settings changes global UI preferences, not project-local resource order.

keyboard

Rename visible labels from agent left/right to resource left/right. Keep stored action ids if needed for compatibility.

shell

A future Shell panel may reset remembered layout or Corner Peek preference, but it should not appear before the feature exists.

contracts

No SQLite, MCP, CLI, runtime, or settings persistence change unless a specific preference already exists.
